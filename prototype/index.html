📝 What's missing / needs adjustment

  • Overlap engine (PLANNIT): auto-finding best common slots from everyone's grids — flagged for a later session. Grid + colors are in; the math isn't.
  • Location search: currently canned places (YMCA, Fairview, Don Mills, Bayview). Needs: how locations get added to a network, and region vs. exact-place search rules. Marked TBD.
  • Time-range replies: the reply picker enforces staying inside the poster's range, but conflicting sub-ranges from two friends (6–7 vs 6:30–7:30) aren't designed yet — merge? vote? poster picks?
  • Custom activity trackers: the 3 tracker types cover count / measure / ladder, but the "create goal" wizard (pick unit, direction, milestones) is a stub — needs a real flow.
  • Universal logger: fan-out currently covers weekly chart, all-time stats, and the bench/swim trend cards via simple tag matching (Gym+Chest → bench, Swim+Distance → swim time). A real version needs a mapping you can edit per goal. LATER
    • \n
  • Smart recommendations: v0 ships 3 hardcoded recovery rules (legs→run, back→swim, 3 hard days→rest). The real version needs a proper muscle-group / intensity model per activity. LATER
  • Profile PIN: stored on this device only — fine for a prototype, but real accounts need actual auth eventually (still email-free options exist: passkeys).
  • Notifications: nothing yet for "someone joined your plan", "goal congratulated", "invite filled". Probably a bell in the header.
  • Groups vs circles: privacy circles, PLANNIT send-groups, and SEARCH groups are three separate ideas — they should probably be one "group" object used everywhere.
  • Live status: the LIVE pill in location search implies real-time check-ins — needs a decision: automatic (scary) vs manual "I'm here" (safer).
  • Editing/deleting posts after friends have replied with sub-ranges — what happens to their replies?
  • Names: SCHD / FRDS / GLPR / PLANNIT are placeholders — GLPR especially reads unclear.
  • Not built yet (by design): real accounts, friend requests, persistence — everything resets on refresh. It's a look-and-feel prototype.
